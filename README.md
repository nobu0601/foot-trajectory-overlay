# foot-trajectory-overlay（足元軌跡カウントツール）

mp4 動画に映る人物を画像解析で追跡し、**足元の通り道（軌跡）を動画の最初のフレームにすべて重ねた画像**を作ります。
その画像を見ながらマウスで**カウント線**を引くと、**線をまたいだ人数（向き別・合計）**がその場で表示されます。
エスカレーター・階段・通路などの**エリアごとに、最も多く数えられるカウント線の候補を3本提案**することもできます。

- 人物検出: YOLO11（ultralytics）／追跡: ByteTrack
- 解析は**全フレーム**で行います（間引きなし）
- 足元の位置: 人物の枠の「下辺の中央」
- GPU なしの Windows PC で動きます

## 使い方（Windows）

### exe 版（おすすめ・オフラインPCで使える）

Python のインストールは不要です。インターネットにつながっていない PC でも動きます。

1. リポジトリの **Releases** から `FootTrajectoryCounter-windows.zip` をダウンロードします（USBメモリ等でオフラインPCへ移して構いません）。
2. zip を展開し、`FootTrajectoryCounter` フォルダ内の **`FootTrajectoryCounter.exe`** をダブルクリックします。
   （mp4 ファイルを exe にドラッグ＆ドロップすると、その動画の解析からすぐ始まります）

- フォルダごと置いて使ってください（exe だけを取り出すと動きません）。
- 検出モデル（標準・高精度の2種類）は同梱済みで、ネットへの接続は一切行いません。
- 初回起動は 10〜20 秒ほどかかることがあります。
- うまく動かないときは `%LOCALAPPDATA%\FootTrajectoryCounter\log.txt` にエラー内容が残ります。

### Python 版

1. [Python 3.12](https://www.python.org/downloads/) をインストールします（インストール時に「Add python.exe to PATH」にチェック）。
2. このリポジトリをダウンロードして展開します（緑の「Code」ボタン →「Download ZIP」）。
3. `run.bat` を**ダブルクリック**するとアプリが開きます（初回だけライブラリと検出モデルを自動でダウンロードするため、数分かかります）。

### 操作（右側の手順 ①〜⑤ に沿って進めます）

画面の右側に「①解析 → ②確認 → ③候補 → ④線 → ⑤出力」の手順が並び、いまの手順の操作だけが表示されます。
各手順の下の「次の手順 →」で進み、上の番号ボタンでいつでも戻れます（済んだ手順は緑の文字になります）。
画像の下には、いま見えている印の意味が表示されます。

**① 解析** — **「動画を選んで解析を始める…」** で mp4 を選びます。画面の下に進み具合と残り時間が出ます（「中止」で止められます）。
解析済みの結果を開く・たくさんの動画をまとめて処理する（一括処理）もここからです。

**② 確認** — 足元の通り道（追跡線）を確認します。

- 線 = 1人分の足元の通り道（人ごとに色分け）、丸 = 歩き始め、矢印 = 歩き終わりと向き
- 足元が画面の外（下端・左右の端）に出たところで線は終わります。戻ってきた人は別の番号の線になります
- **追跡線の太さ**（1 が最も細い1px線）、**背景の暗さ**、**表示する時間帯**（その時間帯に映った人だけ表示。人数の集計には影響しません）、ID番号・座標の格子の表示を変えられます
- **誤判定らしい追跡線**を灰色の点線で表示し、一覧で確認できます（下の「誤判定らしい追跡線」）。**判定基準**（種類ごとのON/OFFと数値）もここで変えられ、すぐ反映されます

**③ 候補（任意）** — エリアを決めて、数えやすいカウント線の候補を自動で探します（下の「カウント線の候補」）。

**④ 線** — カウント線を決めます。

- 画像を**2回クリック**（始点 → 終点）で線を追加。**線の端の丸をドラッグ**して位置を調整できます。右クリック / Esc で引きかけの線を取り消し
- 線の中央の**矢印の向きに通った人が IN**、逆向きが **OUT** です。逆なら **「IN と OUT を入れ替え」**
- **「名前を変える…」**（または一覧をダブルクリック）で、線に名前（例: 改札口）を付けられます
- 一覧に IN・OUT・合計・**重複**・推定範囲・信頼度が出ます。線を選ぶと、点が低い理由と直し方、画像に数えた位置（赤い点）・追跡が途切れた所（橙の×）・すり抜けた所（紫の○）が出ます
- **重複**: 同じ人が短時間に線をまたぎ直した回数です。何秒以内を重複とするかは「重複カウントの警告」で変えられます（既定 1秒）。重複がある線は一覧で色が付きます

**⑤ 出力** — **カウント線を JSON で書き出し**たり、**JSON から読み込ん**だりできます（下の「カウント線の JSON」）。いま表示している画像も保存できます。
人数などのファイルは、操作のたびに自動で保存されています。

### たくさんの動画のカウント線を続けて設定する（連続設定）

1. **① 解析** の「結果を順にカウント線設定する（連続設定）…」で、解析結果の入ったフォルダ（一括処理の出力フォルダなど）を選びます。
   一括処理が終わった画面の「続けてカウント線を順に設定する ▶」からも始められます。
2. 1本目の結果が **④ 線** の画面で開きます。線を引いて名前・向きを決め、**「保存して次へ ▶」（または PageDown キー）** で次の動画へ進みます。PageUp で前へ戻れます。
3. **「線がない動画には、前の動画の線を引き継ぐ」** にチェックがあると、次の動画に前の線がそのまま置かれます（画像の大きさが違えば座標を合わせます）。同じカメラなら、確認して次へ進むだけです。
4. 進めるたびに、全動画・全カウント線の人数を **`all_counts.csv`**（選んだフォルダの中）にまとめます。線のない動画は「（カウント線なし）」と出るので、設定漏れが分かります。

`all_counts.csv` の列: 動画, 結果フォルダ, 線, IN, OUT, 合計, 重複, 推定下限, 推定上限, 信頼度, 評価, 理由

### たくさんの動画をまとめて処理する（一括処理）

1. **① 解析** の **「まとめて処理する（一括処理）…」** を押します。
2. **「フォルダを追加…」**（中の動画をサブフォルダも含めてすべて）や **「ファイルを追加…」**（複数選択可）で動画を追加します。外したい動画は選んで「選んだ動画を外す」。
3. **出力フォルダ**を確認し（既定は動画のフォルダ内の `重畳画像`）、**「一括処理を開始」** を押します。進み具合と残り時間が表示され、「中止」で止められます。

出力フォルダの中身:

| ファイル | 内容 |
|---|---|
| `動画名.png` | 足元軌跡の重畳画像（動画ごと）。サブフォルダの動画は `サブフォルダ名_動画名.png` |
| `results/動画名_overlay/` | 各動画の解析結果。「解析結果を開く…」で開くと、カウント線を引いたり候補を提案させたりできます |
| `batch_summary.csv` | 動画ごとの状態（完了・失敗など）・人数・処理時間の一覧 |

- 開けない動画があっても止まらず、残りを処理します（一覧に「失敗」と理由が出ます）。
- 「解析済みの動画は飛ばす」にチェックがあると、途中で止めても続きから再開できます。
- 一覧の行をダブルクリックすると、その動画の結果をメイン画面で開きます。
- 終わったら **「続けてカウント線を順に設定する ▶」** で、そのまま連続設定に進めます。

### カウント線の候補（③ 候補）

1. 右側の手順 **③** を開きます。
2. **「自動で見つける」** を押すと、人の通り道が集中している場所がエリア（水色）になります。
   - 表でエリアを選び、**種類**（エスカレーター・階段・通路・その他）を設定します。
   - 形がずれていたら、**角の丸をドラッグ**して直します。
   - 足りないエリアは **「手で囲む」** → 画像の上で角を順にクリック → **Enter**（またはダブルクリック）で追加できます。右クリックで1つ戻ります。
3. **「候補を探す」** を押すと、エリアごとに最大 **20,000本**（本数は変更可）の候補線を評価し、上位3本を緑の点線で表示します。
4. 表で候補を選ぶと白く強調され、**ダブルクリック**（または「選んだ候補をカウント線にする」）でカウント線になります。名前と向きは ④ で決めます。

候補の選び方:

- 候補線は、エリアの**中心線に沿って約1pxおき**に、その場所の**人の流れに直角（±20°、1°きざみ）**で、エリアの縁から縁まで引きます。流れと平行な線や、むやみに長い斜めの線は作りません。交差点のように流れが2方向ある場所では、それぞれの流れに直角な線を作ります。
- **誤判定らしい追跡線**（② で確認）が通る位置には引きません。
- まず全候補を高速な方法でふるいにかけ、上位400本を実際のカウント処理と同じ方法で数え直し、上位30本の**信頼度**を出します。
- 順位 = **数えた人数 × 信頼度÷100**。位置が離れた上位3本を選びます。水平・垂直から3°以内の線は、評価が下がらなければ水平・垂直にそろえます。
- 表の見方: **数えた人**（線をまたいだ人数）、**割合**（エリアを通った人のうち数えた割合）、**通過**（往復した人は2回）、**重複**（同じ人を短時間に重ねて数えた回数）、**信頼度**。

### 信頼度の見方

目視の正解がなくても、線の周りの足元軌跡に残る「数え間違いの痕跡」から信頼度（0〜100点）と推定範囲を出します。

| 指標 | 見ていること |
|---|---|
| 位置ずらしの安定性 | 線を少しずらす・傾ける・伸縮した10本で数え直し、人数がぶれないか |
| 途切れ | 線の近くで追跡が途切れて別IDになっていないか（数え漏れの元） |
| すり抜け | 線の端の外側（エリアの縁まで）を通った人がいないか |
| 二重カウント | 同じ人が短時間（既定1秒・④で変更可）に線をまたぎ直していないか |
| 浅い角度 | 線に対して30°未満の浅い角度で通る人が多くないか |
| 端ぎりぎり | 線の両端10%以内を通る人が多くないか |
| 滞留 | 線のすぐそばで2秒以上立ち止まる人がいないか |
| 混雑 | 線の近くに3人以上同時にいる瞬間の通過が多くないか |
| 誤判定らしい線 | 誤判定らしい追跡線が線を通っていないか |

- 評価: **A**（85点以上）そのまま使える、**B**（70〜84点）理由を確認して使う、**C**（69点以下）引き直しを勧める。
- 推定範囲: 「数えすぎ（二重カウント）を除いた数」〜「数え漏れ（途切れ・すり抜け）を足した数」と、位置ずらしで数え直した最小〜最大を合わせた範囲です。

### 誤判定らしい追跡線（② 確認）

次のような追跡線を自動で見つけ、**灰色の点線**で表示します。人数の集計からは外しませんが、カウント線の候補はこれらが通らない位置に引きます。

| 種類 | 判定の仕方 | 変えられる数値（既定） |
|---|---|---|
| **瞬間移動する** | 1フレームで、歩く人の普通の動きの○倍以上（かつ画像の3%以上）飛ぶ（別の人にIDが乗り移った等） | 倍率（6倍） |
| **じぐざぐで前に進まない** | 1秒ごとの「進んだ距離 ÷ 歩いた道のり」（前進率）が○未満（足元の位置が暴れている）。行って戻った人は対象外 | 前進率（0.30） |
| **人が歩かない場所を通る** | 線の○%以上が、他に誰も通らない場所にある（壁・ガラスの映り込み等） | 割合（70%）、判定する動画の追跡線の本数（10本以上） |

- 種類ごとに ON/OFF でき、数値を変えるとすぐ一覧と画像に反映されます。「既定に戻す」で元に戻ります（設定は `meta.json` に保存）。
- 一覧で選ぶと画像上で白く示されます。誤判定ではない線は「誤判定ではない」にできます。

### カウント線の JSON（⑤ 出力）

「JSON に書き出す…」で、カウント線の情報を次の形で書き出します（結果フォルダにも `count_lines.json` として自動保存されます）。
「JSON から読み込む…」で別の動画の結果にも読み込めます。画像の大きさが違うときは、座標を大きさの比で合わせます。

```json
{
  "format": "foot-trajectory-overlay/count-lines",
  "version": 1,
  "video": "入口カメラ.mp4",
  "image": {"width": 1920, "height": 1080},
  "lines": [
    {
      "name": "改札口",
      "start": {"x": 800.0, "y": 300.0},
      "end": {"x": 800.0, "y": 900.0},
      "in_direction": {"x": -1.0, "y": 0.0}
    }
  ]
}
```

- 座標は画像のピクセル（左上が原点、x は右向き、y は下向き）
- **IN = 始点→終点の向きに立って、左側から右側へ通過すること**。`in_direction` はその移動の向き（単位ベクトル）です
- 手で `in_direction` を書き換えた場合は、読み込むときにその向きに合わせて始点と終点を入れ替えます

結果は動画と同じフォルダの `動画名_overlay/` に**自動保存**されます（「保存フォルダを開く」ボタンで開けます）。
次回は「解析結果を開く…」でこのフォルダを選ぶと、解析し直さずに続きから線を引けます。

### 保存されるファイル

| ファイル | 内容 |
|---|---|
| `overlay.png` | 最初のフレームに全員の足元軌跡を重ねた画像 |
| `count_result.png` | 上の画像＋カウント線＋線ごとの人数 |
| `counts.csv` | 線ごとの人数（線の名前, 座標, IN, OUT, 合計, 重複, 推定範囲, 信頼度, 評価, 理由） |
| `count_lines.json` | カウント線の情報（名前・座標・IN の向き・画像の大きさ） |

| `first_frame.png` | 何も描いていない最初のフレーム |
| `tracks.csv` | 足元座標の生データ（`track_id, frame, time_sec, foot_x, foot_y`） |

CSV は Excel でそのまま開けます。

## 数え方のルール

- 重畳画像と同じく、足元の座標を少しならしてから判定します（画像で見た線と結果が一致します）。
- 足元が線の上で小刻みに揺れても何度も数えないよう、線から少し離れて初めて「渡った」とみなします。
- 線の端より外側を回り込んだ人は数えません。
- 同じ人が線を行って戻った場合は、IN と OUT に1回ずつ数えます。
- 足元の位置の揺れで二重に数えないよう、線から画像サイズの1%（768px幅なら約8px）以上離れて初めて「渡った」とみなします。
- 人物が物陰に隠れて追跡IDが途切れると、同じ人が別IDになることがあります。人の重なりが多い場所より、見通しのよい場所に線を引くと正確になります。

## 処理時間の目安

CPU 4コアで、768×432・12fps・50秒の動画が約25秒。
フルHD・30fps の動画では、動画の長さの数倍かかることがあります（解析は全フレームで行うため）。
精度を上げたいときはツールバーの「検出モデル」を「高精度」にします（約3倍遅くなります）。

## コマンドで使う場合

画面を使わずに処理することもできます。

```bat
rem 解析して重畳画像を保存
.venv\Scripts\python.exe -m foot_overlay 動画.mp4 --line-width 4

rem フォルダ内の動画をまとめて処理し、重畳画像を1つのフォルダに出力（exe 版は --batch）
.venv\Scripts\python.exe -m foot_overlay.batch 動画フォルダ -o 出力フォルダ

rem エリアを自動検出し、エリアごとに 20000 本評価してカウント線の候補を3本ずつ提案
.venv\Scripts\python.exe -m foot_overlay 動画_overlay --suggest

rem アプリで書き出したカウント線の JSON を読み込んで数える
.venv\Scripts\python.exe -m foot_overlay 動画_overlay --lines-json count_lines.json

rem 保存済みの結果に、座標を指定したカウント線を引いて数える（複数指定可）
.venv\Scripts\python.exe -m foot_overlay 動画_overlay --line 100,300,600,300 --line 400,100,400,500
```

exe 版では `FootTrajectoryCounter.exe --cli 動画.mp4 ...` で同じことができます（結果はファイルに出力されます）。

主なオプション: `--model yolo11s.pt`（高精度）、`--imgsz 960`（遠くの小さい人を見逃すとき）、
`--conf 0.4`（誤検出が多いとき）、`--min-points 20`（短いノイズ軌跡を除く）、`--max-frames 300`（お試し）。
すべてのオプションは `--help` で確認できます。

## exe の作り方（開発者向け）

GitHub Actions（`.github/workflows/build-windows.yml`）が Windows 上で自動的に作ります。

- `v0.2.0` のような `v` で始まるタグを push すると、ビルド・動作確認のあと Releases に zip が公開されます。
- Actions 画面の「Build Windows exe」→「Run workflow」で手動実行もできます（zip は実行結果の Artifacts から取得）。

手元の Windows で作る場合は、`models/` に `yolo11n.pt` と `yolo11s.pt` を置いてから次を実行します。

```bat
pip install -r requirements.txt pyinstaller
pyinstaller --noconfirm FootTrajectoryCounter.spec
```

`dist\FootTrajectoryCounter\` に exe 一式ができます。

```txt
  session.py    結果フォルダの読み書き、表示設定、カウント線・エリア・候補の状態
  export.py     画像・CSV の保存（日本語パス対応）
  runtime.py    exe 化したときの同梱モデルの場所・オフライン設定
  __main__.py   コマンドライン
launcher.py     exe の入口（--cli でコマンド版、--batch で一括処理）
FootTrajectoryCounter.spec  exe 化の設定（PyInstaller）
tests/          判定・描画・保存のテスト（モデル不要）
```
